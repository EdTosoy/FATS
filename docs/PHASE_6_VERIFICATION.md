# Phase 6 — explainable resume matching verification

Implemented locally on **2026-10-16 (Asia/Manila)** with Node **24.21.0**, pnpm **11.27.0**, Next **16.4.0**, PostgreSQL **17**, and sandboxed system Chromium. Phase 6 started from a clean Git working tree; no user changes were discarded. No commit, push, publication, deployment, new dependency, or live-provider request was performed. Development/user databases, real resumes, and existing browser workspaces were not test targets.

## Delivered behavior

Verified users select an exact resume version within an application, review locally extracted PDF/DOCX and saved job text, and explicitly consent before external transmission. Uploads never trigger extraction/analysis. The comparison leaves original bytes, submitted-version associations, applications, and interviews unchanged. Results show quoted requirements, supported required/preferred priorities, exact resume evidence, partial/undocumented/unclear classifications, and cautious application-written suggestions. No scores, hiring probabilities, fabricated qualifications, or unconstrained generated advice are accepted.

Reports preserve owner, application, immutable resume version, job-description revision/hash, source snapshot, and configuration. Description edits make earlier reports visibly outdated, including after reverting wording; status-only changes do not. Uploads leave old analyses intact. Explicit reruns create separate reports. Deleting derived reports does not change original records; reports protect document/application parents and block JSON replacement, alongside existing interview/submitted-link rules.

The provider-independent server interface has an initial OpenAI Responses adapter pinned to `gpt-5.4-mini-2026-03-17`, strict JSON Schema, `reasoning.effort: none`, `store:false`, bounded output, timeouts, safe errors, and no tools/retries. Credentials remain server-side. Missing configuration gives an honest unavailable state. Automated fixtures are labelled **Automated test fixture — no live AI** and restricted to the dedicated loopback test database.

See [matching design, security, provider sources/pricing, and limitations](MATCHING.md), [configuration](LOCAL_CONFIGURATION.md), and [recovery](DATABASE_RECOVERY.md).

## Security and recovery decisions

An uncached live verified session determines ownership. The private same-origin API verifies both parents, rejects cross-origin/stale-account requests, bounds bodies, and accepts actions/IDs rather than client ownership/source text. Composite foreign keys forbid cross-account references. Original bytes are size/hash checked; reports render escaped text. Recognized source instruction attacks are rejected before sharing, the provider has no tools, and only bounded validated citation/classification structures are accepted. Pattern filtering is not comprehensive prompt-injection detection.

PDF.js 6.4.299 extraction uses a native worker, 10-second deadline, V8 limits, 30-page ceiling, and no action/scripting/link execution. DOCX reuses bounded ZIP/CRC/Open XML validation and saxes 6.0.0 body parsing without external references. Resume text is limited to 24,000 characters/200 segments; combined input is at most 48,000 UTF-8 bytes including segment metadata. Empty, unsupported, malformed/failed, and limit states remain distinct. Extraction admission and daily caps limit processing separately from provider calls.

Sharing requires source review and explicit confirmation. Best-effort contact removal cannot guarantee anonymity. No raw files, filenames, storage keys, account/application IDs, or profile metadata are sent; identifiers can remain in reviewed text. Sensitive payloads, parser diagnostics, credentials, and raw provider errors are not logged. `store:false` does not establish zero provider retention. Default durable UTC-day caps reserve 5/account and 20/global attempts before calls; failures count, report deletion does not reset usage, and idempotent retries do not call again. These bound attempts, not currency spending.

Exact cited excerpts must exist in their claimed normalized/redacted source; FATS computes offsets. Unknown fields, invented excerpts/claims, scores, and unsupported classifications fail validation. Demonstrated claims require conservative lexical/numeric coverage and reject recognized negation/learning wording; partial claims require evidence/overlap. These guards can reject valid paraphrases and cannot prove semantic truth, real qualifications, or complete coverage. The UI calls outputs suggestions to review. Absence from a resume is never proof of lacking a skill. Live-model accuracy is **not verified**.

JSON v1 excludes documents/submitted links, reports/reviewed text, configuration, usage, and internal job revisions. Replacement is guarded at preview and confirmation. Full local recovery uses the PostgreSQL dump + version 2 manifest + paired private files with exact migration compatibility, independent targets, stopped application, and explicit confirmation. The real drill preserves completed report/source/configuration equality, document bytes/metadata/links, and counters. Restore discards extraction previews and marks in-flight attempts interrupted with no result/source text, revokes sessions/recovery tokens, and never contacts a provider. Missing/corrupt/metadata-only bundles still fail; SQL rollback retains copied private bytes after a restore attempt.

Previews expire after 15 minutes. Running attempts older than five minutes become interrupted on later comparison access. Finished reports expire after 30 days and are deleted on the owner's later comparison access. Cleanup is opportunistic: inactive accounts can retain expired text longer. No scheduled purge, provider-side deletion, or removal from earlier archives is claimed.

## Findings corrected

- Strict TypeScript required narrowing the inherited Playwright single-server config and explicitly typing the repository retry-result union. The failed checks/build were corrected and rerun successfully.
- An unused test-only import failed the zero-warning lint policy; it was removed and full lint passed.
- Current official docs identified the initially considered GPT-4.1 mini model as deprecated. The adapter now pins the supported GPT-5.4 mini snapshot; no live request had been made.
- Mixed scanned/text PDFs now reject unreadable image-only pages; DOCX processing limits retain a distinct state.
- Evidence guards reject compound requirements when only one component is covered and compare numeric tokens exactly. Assessments still require human review.
- Recovery explicitly tests in-flight interruption and preview revocation, alongside completed-report equality and exact byte recovery.

## Limitations and next slice

This is a tested local foundation, not hosted readiness or a validated hiring assessment. No live AI evaluation was run. OCR and some layouts/headers/text boxes/image text are unsupported or omitted. Redaction can leave identifiers or remove useful text. Citation/lexical checks cannot guarantee semantic truth; valid paraphrases can be rejected and requirements omitted. Injection detection is incomplete. V8 limits are not full native-memory/OS isolation; DOCX parsing is in-process. There is no scheduled retention purge or durable background analysis queue. Crashed calls are not automatically retried and can incur charges. Files/reports/archives are private but not encrypted at rest by FATS. Phase 5 storage/hosted-recovery limits remain.

Firefox/WebKit, native mobile browsers, full assistive-technology conformance, live provider settings, standalone dependency tracing, hosted abuse controls, and off-device recovery were not tested. Earlier extension native-docking automation limits remain. No rewriting, generation, templates, chatbot, interview simulation, research, crawling, billing, or cloud deployment was added.

Recommended next slice: **separately authorize a synthetic live-provider evaluation with an explicit budget**, measuring coverage, false positives, paraphrases, adversarial inputs, and failures before enabling real resumes. Separately scope scheduled retention and isolated extraction before hosting. Stop after Phase 6.
