## Neon connections and migrations

For the later account slice, select a fresh Neon PostgreSQL **17** database to match local verification, in the same region as Functions. Use separate empty Preview and Production databases/branches; never attach previews to production accounts or clone private data for routine tests. Retain `pg`/Kysely/Better Auth; Neon managed Auth and other Neon services are unnecessary.

The existing command is **`pnpm db:migrate`**, loading `apps/web/.env.local` and running `apps/web/scripts/migrate.mjs`. It deliberately refuses remote hosts. **It cannot migrate Neon today.** The shared runner applies eleven checked-in SQL files in one transaction, takes a transaction advisory lock, and verifies the migration ledger/checksums. Runtime startup does not run migrations.

Minimal follow-up: retain the local command and add an explicit remote migration entry point using `DATABASE_URL_UNPOOLED`, requiring the independently selected Neon host/database and confirmation, TLS verification, sanitized errors, and the existing runner. Its proposed root command is `pnpm db:migrate:hosted` (**not implemented**). Run once from an operator environment against the Preview database, verify all eleven ledger entries and rerun idempotently; repeat separately for Production only after authorization and a recovery checkpoint. Never put migration credentials or migrations in the Vercel build/start command.

**Pooling compatibility is a blocker, not a URL substitution.** Neon’s pooler uses transaction mode and does not support session advisory locks. `handlers.ts:handleAuth` holds `pg_advisory_lock_shared` across the library operation, and account erasure/upload admission also use session locks. A checked-out `pg` client does not pin a pooler backend outside a transaction. Preserve auth/erasure coordination while converting active paths to bounded transaction-scoped locking; test concurrent auth, erasure, retries, and pool release before selecting pooled `DATABASE_URL`. Do not simply remove locks. File-only admission can stay disabled. A direct runtime connection is technically possible for a tiny pilot but is not the recommended pooled configuration or a resolved scalability plan. [Neon pooling limitations](https://neon.com/docs/connect/connection-pooling).

After that repair, use pooled `DATABASE_URL` for app traffic and direct `DATABASE_URL_UNPOOLED` for migrations/recovery. Copy both for the **same intended database**, preserve Neon’s TLS parameters, and verify certificates; never use `rejectUnauthorized: false`. Keep a bounded reused pool (currently max 10 per instance, 5s connect/15s statement timeout); total connections grow with instances. Review Vercel’s pool lifecycle helper when implementing account support rather than swapping database drivers. [Connection lifecycle guidance](https://vercel.com/kb/guide/connection-pooling-with-functions), [node-postgres TLS](https://node-postgres.com/features/ssl).

## Domain, authentication, and email

When domain changes are separately authorized, add `fats.edtosoy.com` to Vercel, then create a Cloudflare **CNAME named `fats`**, using the project-specific target Vercel returns, TTL Auto, **DNS only**. Add any requested ownership TXT record. Keep existing nameservers and unrelated DNS records. Vercel terminates HTTPS; confirm its certificate and HTTP-to-HTTPS redirect before enabling accounts. No Cloudflare proxy, Worker, or extra TLS infrastructure is needed. [Vercel DNS](https://vercel.com/docs/domains/working-with-dns), [Cloudflare proxy status](https://developers.cloudflare.com/dns/proxy-status/).

The auth configuration already requires exact HTTPS origins except loopback, validates signing-secret length, uses `trustedOrigins: [origin]`, Secure/HttpOnly/SameSite=Lax cookies with host-only scope, live database sessions, verified email, and password-reset session revocation. Keep these settings. Requests require matching Host/Origin, writes require same-origin JSON, and the auth wrapper forwards only its allowlisted endpoints/fields. Do not trust arbitrary forwarded hosts, enable wildcard preview origins, add OAuth, widen cookie scope to `edtosoy.com`, or expose the library’s callback/diagnostic routes. [Better Auth security](https://better-auth.com/docs/reference/security).

For a future authenticated preview, choose one stable HTTPS preview hostname and set its exact `BETTER_AUTH_URL`; unset/dynamic auto-detection does **not** work with this repository’s explicit service requirements. Access auth through that hostname. Test Host/Origin forwarding, cookie attributes, verified login, reset/replay/revocation, cross-account access and cross-origin rejection on Vercel before inviting users.

Guest-to-account continuation already preserves a validated relative `/continue-offer/<id>` through sign-in/verification and requires transfer preview/confirmation. **Browser storage is origin-specific:** localhost, changing preview URLs, and `fats.edtosoy.com` have separate guest workspaces. Export JSON on the old origin and explicitly preview/restore it on the new origin before transferring; preserve browser originals. Password recovery does not currently preserve every continuation destination. See [F02 verification](HALLMARK_F02_VERIFICATION.md).

**Email is unresolved and accounts must stay disabled.** `getServices()` rejects hosted auth origins; the only mailer connects to loopback Mailpit, uses a `.test` sender and local-only non-TLS SMTP. No hosted provider, verified sender, credentials, SPF/DKIM, deliverability, or recovery delivery has been configured. Select a transactional provider and verify its sender/DNS in a follow-up; do not merely remove the hosted-origin guard or disable email verification. [Better Auth requires an email provider](https://better-auth.com/docs/concepts/email).

The current `void mailer(...).catch(...)` can be interrupted after a serverless response. Replace it with supported request-lifetime scheduling, such as Next.js `after()`, while retaining awaited token persistence and safe resend/failure behavior; verify registration, OTP, reset, and interrupted delivery. No durable queue is needed for the first bounded beta. [Next.js `after`](https://nextjs.org/docs/app/api-reference/functions/after).
