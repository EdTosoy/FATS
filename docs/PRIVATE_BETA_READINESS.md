# Private beta readiness — Part 1

Assessment date: 2026-10-16. Baseline: `daaffe4` (`feat(backups): support portable offer history`), following Offer Desk `b903a36`. The initial `main` tree was clean, with zero ahead/behind against the locally recorded `origin/main`. No remote fetch was used to infer the remote's current state. Offer Desk 1.1 was committed before this work. Changes in this assessment remain for manual review; no commit, push, deployment, paid infrastructure, or AI request was made.

## Readiness decision

**Do not invite users to entrust real applications, resumes or employment documents to a remote beta yet.** The core local workflows have automated evidence, but hosted verification, file safety/admission controls, operational storage/recovery and complete erasure are unresolved. A successful local build or restore drill does not resolve those risks.

The product is suitable for a **supervised local usability rehearsal using synthetic accounts and supplied synthetic documents**, after the moderator configures an isolated workspace and completes the rehearsal in the [test plan](PRIVATE_BETA_TEST_PLAN.md). This is not permission to collect real documents or expose the local server/inbox through a tunnel. Human sessions, accessibility certification and real-user success rates have not been measured.

The inspected development environment has matching/provider configuration disabled but **no `FATS_DOCUMENTS_DIR` configured**. The directory was not selected or the private environment file rewritten on the user's behalf. Automated document journeys use a dedicated test directory. Configure a persistent private directory and verify it in the actual rehearsal workspace before inviting even synthetic-data participants.

## Security and recovery evidence

- Live verified sessions establish ownership on workspace, offer and document endpoints. Client ownership fields are rejected; stale account headers detect changed accounts but do not grant authority. Composite owner foreign keys prevent cross-user parents/version links. Account data/bytes never fall back into guest storage on failed authentication.
- Exact Host/Origin checks, same-origin JSON writes, bounded request bodies, no-store/private responses, parameterized SQL and narrow auth endpoint allowlist remain intact. Session cookies are HttpOnly/SameSite=Lax; Secure is conditional on HTTPS, so local HTTP is not a hosted transport-security demonstration.
- Verification codes/identifiers are hashed, expire, rotate and cannot be consumed twice. Password recovery is generic/rate-limited; reset consumption, password update and all-session revocation are transactional. Existing integration tests exercise invalid/replayed/concurrent requests and rollback. Mail delivery is asynchronous after token persistence, without a durable queue.
- Documents use owner-checked endpoints, immutable private 0600 bytes under a canonical 0700 directory, exclusive publication, SHA-256/size validation and quota locks. Download/preview use safe disposition/MIME, no-store, nosniff, sandbox CSP and same-origin restrictions. Tests cover cross-account denial, malformed/oversize/interrupted uploads, missing/corrupt bytes, retry/publication failures and deletion restrictions. Orphans/partials can remain private after ambiguity; there is no automatic orphan garbage-collection service.
- Offers retain decimal strings, immutable ordered revisions, optimistic versions and idempotent request IDs. Checklist/decision writes and restore imports are transactional. No decision changes interview history. Repeated/stale/conflicting imports do not overwrite decisions. Original document IDs in portable JSON create no new authorization or foreign key.
- Operator tests take a real PostgreSQL archive plus manifest/private file bundle, restore into disposable independent targets, compare records/bytes/links and revoke sessions/recovery/staging. Invalid targets/bundles, in-use targets and failed post-restore validation preserve prior records. Stored comparison fixtures are recovered without provider execution. No production/user restore, off-device recovery or timed disaster exercise was performed.
- Private env files are Git-ignored and mode 0600; tracked env-name matches are generated `next-env.d.ts`, not secrets. Logs reviewed use fixed errors rather than tokens, credentials or document text. No remote fonts/analytics were added. The production dependency registry audit reported zero known advisories at execution time; it is not a malware check, proof of parser safety or independent dependency audit.

## Bounded fixes completed

1. Added `server/matching-access.ts` with an exact server opt-in, `FATS_AI_MATCHING_ENABLED=1`. Unset, `0` and unknown values deny all matching actions with private/no-store `403 MATCHING_DISABLED`. The route guards before `getServices`; the handler guards before any dependency. The server page omits the matching panel. Provider credentials alone cannot expose it, and stale clients cannot bypass the endpoint. Ordinary browser configurations explicitly disable it. Dormant fixture suites have an explicit test-only opt-in so their prior implementation remains testable when separately authorized; they were not run here.
2. Corrected Help's outdated replacement-only description: v2 adds missing records/skips identical records/blocks conflicts; legacy v1 requires replacement confirmation. Clarified unavailable letter references, complete operator file recovery, and account Settings' offer/file backup boundary. No persistence/domain/schema migration was needed.

The AI regression first failed with actual status 200 for a verified synthetic user and synthetic unused provider credentials. It now passes with 403. No compare/extraction/provider call was made to reproduce it. New unit tests assert denial before dependency access, and browser checks verify the panel makes no matching request and direct GET/prepare/compare/delete requests are denied. No Phase 6 implementation or historical evaluation record was removed.

## Before invitations

For the local synthetic study, the moderator must configure a separate persistent document directory and isolated account workspace, use an isolated browser profile, rehearse the exact tasks, keep inbox/credentials private, verify matching remains disabled, and agree consent/retention/stop conditions. Existing application/interview/offer records must never be used as participant fixtures.

For a beta holding real personal records, close B1–B5 as applicable and explicitly accept or resolve important findings with named owners and evidence. The next non-AI milestone should be narrowly scoped **beta data protection and operations**: complete erasure, upload admission/file-safety handling, durable storage and a measured recovery drill, plus authorized hosted identity/delivery if remote access is intended. Follow with the moderated study and fix observed novice friction. No new product phase is recommended.
