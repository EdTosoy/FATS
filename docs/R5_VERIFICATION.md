# R5 — Hosted Sidekick integration

Date: 2026-11-06. Scope stops at R5. No commit, push, deployment, production migration, authentication repair, live AI call or Chrome Web Store publication.

## Implementation

- Shared domain allowlist and packaged content-script matches add exactly `https://fats.edtosoy.com`, retaining both port-3000 loopback origins. Destination selection starts empty and requires a deliberate choice. The selected address and guest/account workspace are shown before confirmation. No automatic fallback or extension-owned account access exists.
- Reuses the bounded JSON-LD/HTML extractor and inert text conversion. Carries explicit salary bounds/currency/period, arrangement, seniority, technologies, qualifications and publisher calendar date through correction, review, handoff, confirmation and existing guest/PostgreSQL persistence. Unknown/ambiguous values stay empty. Optional fields use R1 validation; unrelated application metadata is discarded at the capture boundary. Legacy drafts still validate; legacy location/arrangement text remains compatible.
- Retains Capture → Review → Open FATS → Confirm and save. Existing repositories handle posting/ID duplicates and retries; expired sessions block account writes without guest fallback. Guest confirmation remains available when only account access is unavailable. No employer application is submitted.
- No new permissions, dependencies, schema or infrastructure. Worker sender identity, top-frame/path/origin checks, origin-bound draft retrieval, 15-minute expiry, session-only pending storage and URL privacy remain in place. No cookie permission, broad host access, external-message listener, remote code or background scraping.
- `tsconfig.tools.json` resolves the extension's already-installed Chrome declarations so unit tests can import and execute the actual service-worker module without adding dependencies or suppressing lint rules.

## Hosted verification boundary

**Live hosted end-to-end verification is NOT RUN successfully.** Hosted registration is reported to fail with “Account storage is temporarily unavailable.” R5 does not fix authentication or bypass Vercel protection.

An initial simulated navigation escaped Playwright interception and reached Vercel's login protection; no authenticated action or save occurred. The final simulation holds extension-created hosted tabs at `about:blank`, asserts the actual worker-selected destination URL, then navigates through Playwright routing. All simulated hosted requests are fulfilled by the isolated local production server. This verifies the real HTTPS-origin bridge, confirmation UI and guest persistence, while substituting the initial tab navigation/transport. It does not verify public DNS/TLS, Vercel protection, hosted database/email availability or hosted account saving.

Real local account coverage verifies registration/email verification, login return to the exact opaque handoff, session expiration during confirmation, retained edits, new-tab reauthentication, PostgreSQL save, no guest copy, duplicate reload and absence of account email/password from the pending extension draft. Local account coverage cannot establish live hosted account correctness.

Native Chrome dock resizing/pinning, Chrome Web Store review, other browsers, physical-device and assistive-technology verification are not performed. Automated tests drive the packaged panel document in an extension tab, with real toolbar permission, worker, injected extractor and bridge. No extension is installed into the user's current browser profile. Representative panel and desktop/mobile confirmation screenshots were visually reviewed and are retained locally in `.fats-private/r5/screenshots/`; development results are in `test-results/r5-development/`. The three original moodboards and the additional brand board are preserved.
