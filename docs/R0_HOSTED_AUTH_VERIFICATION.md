## Implemented change

Unexpected auth failures now emit `FATS authentication unavailable.` with only a fixed stage and category. Stages distinguish initialization, pool acquisition, the erasure coordination guard, the library call and live-session checks. Allowlisted categories distinguish missing table/column, permissions, database authentication, connection/DNS failures and certificate verification; everything else is `unexpected`.

No error object, message, stack, SQL, arbitrary driver code, request, account identifier, token, connection string or provider response is logged. Expected validation/origin/auth refusals do not emit these diagnostics. Library 5xx responses receive a fixed diagnostic without reading/logging their bodies. Client responses and status handling are preserved. Other handlers retain their existing error behavior.

Tests cover redaction, unknown/opaque driver codes, quiet expected failures, injected pool/library failures, library 5xx responses and successful retry. The hosted migration test now explicitly expects all fourteen real migrations and uses an unapplied synthetic 0015 probe. No probe migration is added to the application.

Email verification, Secure/HttpOnly/SameSite cookies, live sessions, password recovery/revocation, owner-scoped repositories, same-origin checks, rate limits, explicit guest transfer and auth/erasure transaction locks are retained. AI matching and scanner-dependent uploads remain disabled during verification.
