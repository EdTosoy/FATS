## Delivered behavior

Settings now provides client-side JSON export, file selection, validated preview with incoming/current counts, explicit replacement acknowledgment, keyboard cancellation, and success/error feedback. Empty restores warn about removing all records. Unreadable current storage can be recovered only with a valid backup and explicit confirmation; users are told to privately copy the original value first.

The independent `fats-backup` format/version 1 is documented in [BACKUPS.md](BACKUPS.md). It preserves application/interview IDs, timestamps, statuses, notes, and relationships. It excludes unrelated browser storage, extra unknown fields, unsaved drafts, resumes, and other assets. Files are unencrypted, with a 10 MiB UTF-8 limit. Unknown versions are rejected at a future migration boundary, not guessed or converted.

Export reads the one FATS key once. Import stages a validated detached copy without writing, detects changes since preview, then replaces both arrays through one `setItem`. It never clears first. Failed reads, validation, cancellation, stale previews, and failed writes preserve saved data. Provider state updates only after persistence succeeds. This is single-key replacement, not transactional cross-tab locking or a crash-durability guarantee; the [Web Storage algorithm](https://html.spec.whatwg.org/multipage/webstorage.html#dom-storage-setitem) rejects an unstorable value before changing the map.

Storage key/envelope version remains compatible with Phase 1/2. Missing interviews in Phase 1 storage still means an empty collection, without a read-time rewrite. Shared validation now rejects malformed manually edited application timestamps using canonical UTC ISO rules; records generated by earlier phases already use that form. Existing application rules moved unchanged into `application.ts`, with the public barrel exports preserved, to avoid circular imports from shared backup validation.

The brand README formatting issue was only missing blank lines around headings and lists. Prettier corrected spacing; words and asset meanings were preserved. All other brand files and all original moodboards remain untouched.

## Limits and next step

Backups require an explicit download and safe file retention. They are not encrypted or authenticated and include only saved records. Full restore has no merge, automatic undo, migration, or automatic pre-restore download. Users recovering corrupt storage must privately preserve its original raw value through browser developer tools. A schema-valid file may still be wrong for the user's intent; counts and confirmation cannot authenticate content.

There is no lock across tabs; a simultaneous write can race between the preview comparison and the final write. Available browser quota may be below the 10 MiB file limit. Browser/OS crashes, site-data deletion, lost files, and shared-profile privacy remain limitations. No Firefox, WebKit/native Safari, full accessibility audit, or assistive-technology session was run.

Recommended next step: separately scope an unsaved-draft warning for application/interview forms and notes, because backups cannot recover work that was never saved. No further slice was started.
